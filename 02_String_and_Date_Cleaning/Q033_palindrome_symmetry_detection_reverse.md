# Q033: Palindrome & Data Symmetry Detection (`REVERSE`, `LOWER`)

- **Target Role:** Data Analyst / Data Quality Engineer (0–2 Years Experience)
- **Dialect Compatibility:** MySQL (`REVERSE`), PostgreSQL (`REVERSE`), SQL Server (`REVERSE`), Snowflake (`REVERSE`)

## 🏢 Business Scenario
In digital search engines and e-commerce product catalogs (e.g., Amazon Search, Flipkart, Algolia), search query logs are continuously monitored for query quality, automated testing traffic, and bot activity.

Quality assurance engineers frequently identify mirrored or symmetrical inputs—known as **Palindromes** (words that read identically forwards and backwards, such as *Racecar*, *Kayak*, *Level*, or *Madam*)—which are generated by synthetic load-testing bots or stress-testing crawlers.

The Search Quality Analytics team requires an audited extract of high-volume search queries where:
1. The keyword is a valid palindrome evaluated **case-insensitively**.
2. The search query generated significant volume (`search_count >= 100`).
3. Output preserves all query details including `search_count`.
4. Sorted by `search_count DESC, query_id ASC`.

## 💡 Production SQL Solution

```sql
SELECT 
    query_id, 
    search_keyword, 
    search_category, 
    search_count 
FROM search_query_logs 
WHERE LOWER(search_keyword) = REVERSE(LOWER(search_keyword)) 
  AND search_count >= 100 
ORDER BY search_count DESC, query_id ASC;
```

## 🧠 Interview Defense & Technical Takeaways

### 1. Case-Insensitive Symmetry
- In TitleCase inputs like `'Racecar'`, a direct `REVERSE('Racecar')` yields `'racecaR'`.
- In binary or case-sensitive collations (e.g., `utf8mb4_bin` or PostgreSQL `C`), `'Racecar' = 'racecaR'` evaluates to `FALSE`.
- Wrapping both sides with `LOWER()` normalizes casing prior to reversing:
  $$\text{LOWER}('Racecar') = 'racecar' \equiv \text{REVERSE}('racecar') = 'racecar' \implies \text{TRUE}$$

### 2. Multi-Word Palindromes (Whitespace Strip)
- When dealing with palindromic sentences or phrases (e.g., `'Taco cat'`), whitespace shifts during string reversal (`'tac ocat'`).
- **Whitespace-Agnostic Expression**:
  ```sql
  REPLACE(LOWER(search_keyword), ' ', '') = REVERSE(REPLACE(LOWER(search_keyword), ' ', ''))
  ```

### 3. SARGability & Indexing Hazards
- Applying scalar functions (`LOWER`, `REVERSE`) to indexed columns invalidates standard B-Tree index lookups, precipitating a full table scan.
- **Enterprise Solution**: Implement a deterministic generated/virtual column or a functional index:
  ```sql
  CREATE INDEX idx_search_palindrome ON search_query_logs ((LOWER(search_keyword)));
  ```

## 🚨 Common Interview Traps & Defense

### Trap 1: Collation Sensitivity
- **Interviewer Query:** *"Why is `LOWER()` mandatory if MySQL defaults to case-insensitive collation (`utf8mb4_0900_ai_ci`)?"*
- **Candidate Defense:**
  > *"While default MySQL collations are case-insensitive, enterprise production environments often enforce binary or case-sensitive collations (`utf8mb4_bin`, PostgreSQL default) for exact telemetry and security matching. Writing `LOWER(col) = REVERSE(LOWER(col))` ensures cross-dialect compatibility and prevents collation-dependent bugs."*

### Trap 2: Handling Single-Character Strings
- **Interviewer Query:** *"Is a single character (e.g., `'A'`) considered a palindrome by this query?"*
- **Candidate Defense:**
  > *"Yes, mathematically any single character satisfies $f(x) = f^{-1}(x)$. If the business definition requires non-trivial palindromes, we explicitly append a length constraint: `AND LENGTH(search_keyword) > 1`."*
